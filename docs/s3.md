# Control AI access to S3 object storage

GateRook's MCP Firewall lets AI apps list buckets and objects, read text objects within the endpoint's limits, and holds every upload, copy and delete for your review. It works with Amazon S3 and with storage that speaks S3's API, such as Cloudflare R2, DigitalOcean Spaces, Backblaze B2, Wasabi and MinIO. On Amazon S3 with an IAM role, AWS itself limits each call to what it needs. The [security model](security.md) explains execution controls, explicit Bypass, and the append-only, tamper-evident audit trail.

## Connect Amazon S3

The built-in **S3 object storage** connector (`s3`) calls S3's REST API, signed with SigV4; there is no S3 SDK in GateRook. Leave **Endpoint** empty for Amazon S3 and choose the **Region** of the buckets. Requests go only to `s3.<region>.amazonaws.com` (`.amazonaws.com.cn` in China; GovCloud regions as AWS names them), with the bucket in the host name (`<bucket>.s3.<region>.amazonaws.com`). A bucket with dots in its name is addressed by path instead, because the TLS certificate covers one label. A bucket in another region is reported with its region: add a connection for that region.

Choose the credentials:

- an **access key** (stored encrypted in GateRook), or an **AWS profile** of this computer (`~/.aws/config` and `~/.aws/credentials`). A profile may not use SSO, `credential_source`, `web_identity_token_file` or a `role_arn` of its own; a `credential_process` runs with a warning;
- optionally a **role to assume**, with an external ID in its trust policy.

With a role, **Session policy** defaults to each call's own permissions, which AWS enforces whatever the role itself may do:

| Call | Session policy |
| --- | --- |
| `s3_list_buckets` | `s3:ListAllMyBuckets` |
| `s3_list_objects` | `s3:ListBucket` on the connection's buckets |
| `s3_head_object`, `s3_read_object` | `s3:GetObject` and `s3:GetObjectVersion` on the buckets' objects, `s3:ListBucket` (so that a missing object is a 404), `kms:Decrypt` through S3 only |
| An approved `s3_put_object` | `s3:PutObject` on the one object, `kms:GenerateDataKey` and `kms:Decrypt` through S3 only |
| An approved `s3_copy_object` | `s3:GetObject` and `s3:GetObjectTagging` on the source (with a version, their version actions), `s3:PutObject` and `s3:PutObjectTagging` on the destination, KMS through S3 only |
| An approved `s3_delete_object` | `s3:DeleteObject` on the one object (with a version id, `s3:DeleteObjectVersion`) |

KMS actions carry the condition `kms:ViaService` = `s3.<region>.amazonaws.com`, so buckets encrypted with a KMS key work without allowing the key for anything else. STS accepts 2,048 characters of policy: a bucket list too long for that keeps the actions and allows them on every bucket, and a change on a key too long for it allows its action on that bucket's objects. On prod the session policy can't be turned off. Without a role, each call has every permission of the key or profile: **Test connection** says so, as a warning outside dev.

**Buckets** lists the buckets agents may use (`*` matches any characters, as in `acme-reports-*`). On Amazon S3, an empty list means the buckets of the credentials' own account: every request then carries `x-amz-expected-bucket-owner` with the account that `sts:GetCallerIdentity` reports, and S3 refuses buckets of other accounts. `s3_list_buckets` shows the buckets of the connection's region. Test connection reports the identity AWS sees and the buckets agents may use.

While you fill in the form, GateRook suggests the profiles of `~/.aws/config`, fills in the profile's region, and offers an S3-compatible server that answers on this computer (MinIO's port 9000, LocalStack's 4566) as an **Endpoint**. Once the form can sign in, with the same credentials and session as Test connection, it lists the region's buckets under **Buckets**; without a region yet, or without buckets in it, it offers the regions where the account's buckets are. A profile's `credential_process` never runs for these suggestions.

## Connect S3-compatible storage

Put the service's endpoint URL into **Endpoint**, its region into **Region** and an access key into **Credentials**. Requests then go to that endpoint with the bucket in the path (**Path-style addressing**, on by default); turn it off for a service that wants the bucket in the host name. There are no roles and no session policies outside AWS: give the access key only the buckets and permissions agents need, as R2 API tokens and most providers' keys allow. The endpoint can't be an Amazon S3 host, carry credentials or a query, or have `.` or `..` path segments.

Each request goes through GateRook's egress guard under the environment's address policy: a service on a private network, such as MinIO on a LAN or in Docker, is reached only after its address range is added to **HTTP egress › Allowed private addresses** of the environment's policy. Redirects are never followed and no proxy is used. An `http://` endpoint sends objects and signed requests unencrypted; Test connection warns about it outside dev.

The endpoints and regions below follow each provider's public documentation; check yours in the provider's console. For an endpoint of a provider in the table, the form fills in its **Region** and turns **Path-style addressing** off where the notes say so; once it can sign in, it lists the buckets the access key may list.

| Provider | Endpoint | Region | Notes |
| --- | --- | --- | --- |
| Cloudflare R2 | `https://<account-id>.r2.cloudflarestorage.com` (EU jurisdiction: `<account-id>.eu.r2.cloudflarestorage.com`) | `auto` | The S3 access key of an R2 API token, which can be limited to buckets |
| DigitalOcean Spaces | `https://<region>.digitaloceanspaces.com`, such as `https://nyc3.digitaloceanspaces.com` | `us-east-1` | Path style off |
| Backblaze B2 | `https://s3.<region>.backblazeb2.com`, such as `https://s3.us-west-002.backblazeb2.com` | The endpoint's region, such as `us-west-002` | An application key ID and key |
| Wasabi | `https://s3.<region>.wasabisys.com`, such as `https://s3.us-east-1.wasabisys.com` | The endpoint's region | |
| MinIO | `http://minio.internal:9000`, or its https address | `us-east-1`, unless the server sets another | Add its address range to the allowed private addresses |
| Hetzner Object Storage | `https://<location>.your-objectstorage.com`, such as `https://fsn1.your-objectstorage.com` | The location, such as `fsn1` | Path style off |
| OVHcloud | `https://s3.<region>.io.cloud.ovh.net`, such as `https://s3.gra.io.cloud.ovh.net` | The region, such as `gra` | |

Another service works when it implements S3's SigV4 signatures and the requests below. Bucket names may then also contain capital letters and underscores, as OCI and Cloud Storage allow.

## Bound reads and review exact changes

| Tool | What it does | Default mode |
| --- | --- | --- |
| `s3_list_buckets` | Buckets agents may use, with creation dates | Read only |
| `s3_list_objects` | Keys, sizes and modification times under a prefix; with the default delimiter `/` deeper keys are grouped into prefixes | Read only |
| `s3_head_object` | Size, content type, ETag, version, storage class, encryption, object lock and user metadata of one object | Read only |
| `s3_read_object` | Up to 256 KB of one text object from an offset | Read only |
| `s3_put_object` | One object with text content, created or replaced | Approval |
| `s3_copy_object` | One object copied to a key of a bucket of the connection | Approval |
| `s3_delete_object` | One object, or one version of it | Approval |

**Listings** use `ListObjectsV2` with `encoding-type=url` and show keys as they are stored. A page holds at most the endpoint's row limit; `nextCursor` continues it. Cursors are sealed by GateRook and belong to one connection and one request.

**Reads** take one byte range, checked with `If-Match` against the ETag `HeadObject` reported, and stop at a whole UTF-8 character; `nextOffset` continues. `maxBytes` is lowered to fit the endpoint's response size (the text is in the answer twice: its structured content and its text). Only text is read: a text content type (`text/*`, JSON, XML, YAML, CSV, NDJSON, SQL, TOML and `+json` or `+xml` types), or a text file name when the type says nothing (`application/octet-stream`). Binary objects, objects stored with a `Content-Encoding` such as gzip, archived objects that aren't restored, and text in charsets other than UTF-8 and single-byte ones are refused with their metadata. Objects named like files that hold keys, credentials, `.env` settings or Terraform state (`.pem`, `.key`, `id_rsa`, `credentials.json`, `.netrc`, `.tfstate`) are refused by name before any request; `s3_head_object` still shows their metadata. User metadata whose name says it holds a secret (such as `token`, `password`, `secret`, `credential` or `api-key`) is masked, and GateRook's masker then applies to every answer.

**Changes.** The approval shows the HTTP request exactly as it is sent: method, URL, the headers GateRook sets, the body up to 64 KB (beyond that, its size and SHA-256), and the signature masked. Before asking, GateRook looks at the target with `HeadObject`, so the approval says whether the change creates, replaces or deletes an object. What runs is built again from the call and the connection and compared with the approved request first; any difference stops it. A change is never retried: a connection lost after the request was sent, or a server error, reports the outcome as unknown.

- `s3_put_object` writes text of at most the endpoint's request size (**HTTP egress › Max request body** of the policy: 256 KB on dev and stage, 64 KB on prod) and 5 MB, with a text content type (default `text/plain; charset=utf-8`) and up to 2 KB of user metadata. `overwrite: false` sends `If-None-Match: *`, so an existing object stays; `ifMatch` replaces the object only while its ETag is the one given.
- `s3_copy_object` copies within the connection's buckets. The copy keeps the source's metadata and tags unless `contentType` or `metadata` is given, which replace them. A copy of an object onto itself without either is refused.
- `s3_delete_object` without `versionId` deletes the object; a versioned bucket keeps its earlier versions behind a delete marker. With `versionId` it deletes that version permanently.

**Never offered:** presigned URLs, bucket creation and deletion, bucket policies, ACLs and configuration, multipart and binary uploads, and object tags.

**Names.** Bucket names follow Amazon S3's rules on Amazon S3; S3 Express One Zone directory buckets (`--x-s3`) aren't supported. Keys are percent-encoded once, never normalized: a key with a `.` or `..` path segment (also before a `;`), a backslash or a control character is refused, and a key a change writes may not contain invisible or direction-changing characters.

## Verify with moto

For local verification, start the opt-in [moto service](../test-services/README.md) with `scripts/test-services.sh up s3` and run the connector's integration test with `-Pservices`. moto emulates S3 and STS but checks no signature and enforces no IAM policy: GateRook's signatures are checked against AWS's published SigV4 examples and by an independent verifier on every request a fake receives, and the session policies' contents against that fake. These tests don't establish native-image or installer compatibility, nor behaviour against Amazon S3 or the providers above.

AWS documents the [S3 API](https://docs.aws.amazon.com/AmazonS3/latest/API/Welcome.html), [SigV4 for S3](https://docs.aws.amazon.com/AmazonS3/latest/API/sig-v4-authenticating-requests.html), [actions, resources and condition keys for S3](https://docs.aws.amazon.com/service-authorization/latest/reference/list_amazons3.html), [conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) and [session policies](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies.html#policies_session).
