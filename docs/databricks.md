# Control AI access to Databricks SQL

GateRook's MCP Firewall lets AI apps explore Unity Catalog and run Databricks SQL reads on a SQL warehouse, and holds every change for your review. The [security model](security.md) explains execution controls, explicit Bypass, and the append-only, tamper-evident audit trail.

## Connect a workspace

The built-in **Databricks SQL** connector (`databricks`) calls the [SQL Statement Execution API 2.0](https://docs.databricks.com/aws/en/dev-tools/sql-execution-tutorial) and Unity Catalog's REST API of one workspace. There is no Databricks SDK or JDBC driver in GateRook. Choose:

- the **workspace URL**, as the browser shows it: `https://` only, a host name (`*.cloud.databricks.com`, `*.azuredatabricks.net`, `*.gcp.databricks.com`, or another name such as a private link), never an IP address but a loopback one. Every address the name resolves to is checked before each request: private ranges stay allowed for a private link, cloud metadata, link-local and reserved addresses never are. TLS is verified, redirects are never followed, and tokens go to this host only;
- the **SQL warehouse** by its ID, and optionally the **default catalog and schema** of statements;
- how GateRook **signs in**: a service principal with OAuth machine-to-machine (its client ID, and its client secret stored encrypted in GateRook), or a personal access token. GateRook exchanges the client secret at the workspace's own token endpoint (`/oidc/v1/token`, scope `all-apis`) and keeps the token in memory until a minute before it expires; a rotated secret, a changed connection or a refused token signs in again.

Databricks SQL has no read-only session: Unity Catalog's grants are the boundary. Use a service principal with `USE CATALOG`, `USE SCHEMA` and `SELECT` on what agents read, and `CAN USE` on the warehouse; outside dev, **Test connection** warns when calls use a personal access token, which carries every grant of its owner. Test connection names the identity Databricks sees, the warehouse and its state, and the catalogs agents may use, and runs a query only when the warehouse is running, as a query starts a stopped one. The periodic health check reads the warehouse's state and never starts it.

**Catalogs** and **Schemas** (`schema` or `catalog.schema`; `*` matches any characters) narrow what agents may use; empty, every catalog and schema the identity may use. The metadata tools list and describe only what they allow. A statement is refused when it names a catalog or schema off them: every table it names (after `FROM` and the commas of a `FROM` clause, `JOIN`, `INTO`, `UPDATE`, `TABLE`, `VIEW`, `USING`, `CLONE`, `LIKE`, `RENAME TO`, `OPTIMIZE`, `VACUUM` and `DESCRIBE`), every schema and catalog it names, and every function it calls with its schema. A name without a catalog or schema is read in the connection's defaults, which must be on the lists; `SHOW CATALOGS` and `SHOW SCHEMAS` are refused while the lists limit them, as they would show the names off them. GateRook doesn't follow views or functions: a view on the list shows what its owner may read, so the grants stay the boundary.

While you fill in the form, GateRook offers the workspace profiles of `~/.databrickscfg` (or `DATABRICKS_CONFIG_FILE`): the default profile's host (`DATABRICKS_CONFIG_PROFILE`, else `DEFAULT`), and the `warehouse_id` or `http_path` and `client_id` of the profile whose host the form names. It never reads a token or client secret from the file. Once the form can sign in, it offers the SQL warehouses the identity may use, even before the SQL warehouse ID is entered, and fills in the only one, or the only one running. It also offers the catalogs and the schemas of the default catalog. It fills in a default catalog and schema where Catalogs or Schemas need one: the workspace's default when the list allows it, else the list's only match. These are reads of the REST APIs only: no warehouse starts.

## Bound reads and review exact changes

| Tool | What it does | Default mode |
| --- | --- | --- |
| `databricks_list_catalogs` | Unity Catalog catalogs agents may use | Read only |
| `databricks_list_schemas` | Schemas of one catalog | Read only |
| `databricks_list_tables` | Tables, views and their kinds in one schema | Read only |
| `databricks_describe_table` | Columns with types, partitioning, format and comment | Read only |
| `databricks_query` | One `SELECT`, `WITH`, `VALUES`, `TABLE`, `SHOW`, `DESCRIBE` or `EXPLAIN` of a query, with `:name` parameters | Read only |
| `databricks_execute` | One change: DML, DDL of tables, views and schemas, or table maintenance | Approval |

A read runs as one statement on the connection's warehouse, `INLINE` in `JSON_ARRAY` format, with the endpoint's row limit times ten as `row_limit` and 8 MiB as `byte_limit`. It waits on the server for what the call has left (`wait_timeout` of 5 to 50 s, with `on_wait_timeout: CANCEL`, so Databricks cancels it there); when the call has too little time left for that, GateRook polls and cancels it at the deadline. Pass values as `:name` parameters with an optional scalar type (`INT`, `DATE`, `DECIMAL(10,2)`); without one, a whole number is a `BIGINT`, a number a `DOUBLE`, a boolean a `BOOLEAN`, and `null` is `NULL`. Answers keep Databricks' types: a whole number is a JSON number only where JavaScript keeps it exact, `DECIMAL` stays text, a `TIMESTAMP` is ISO 8601 (in UTC when Databricks gives an offset), a `TIMESTAMP_NTZ` ISO 8601 without one, binary values show their first 256 bytes in hex, arrays, maps and structs are JSON when they fit a cell, and long strings are cut to the endpoint's cell size. A large result returns `nextCursor`, which reads on from the same row of the same statement's result chunks without running the query again; Databricks keeps a result for an hour, and so long a cursor lives. Cursors are sealed by GateRook and belong to one connection and one request.

GateRook first reads each statement by the tokens of Spark and Databricks SQL: `'…'` and `"…"` strings with backslash escapes, raw `r'…'` strings, `` `…` `` names, `--` and block comments and `/*+ … */` hints. It refuses what it can't read with certainty: an open quote or comment, a comment inside a comment, a line comment that ends in a backslash (Spark goes on with it on the next line), a backslash in a raw or double-quoted string and one before a quote in any string (readers, and warehouse settings, disagree on what it does there; write `"it's"`), a `$` outside a string (bodies of Python functions), `${…}` (Spark replaces it before it reads the statement, so what runs isn't what GateRook read) and a control character. It also refuses:

- more than one statement, transactions and SQL scripting (`BEGIN`, `DECLARE`, `EXECUTE IMMEDIATE`, `IF`, loops): they run statements GateRook didn't read one by one;
- `GRANT`, `REVOKE` and `DENY`, ownership (`OWNER TO`), row filters and column masks: they set access, which is the boundary GateRook relies on;
- `SET`, `RESET` and `USE`: the session's settings, catalog and schema belong to the gateway;
- `COPY INTO`, the file commands `LIST`, `PUT`, `GET` and `REMOVE`, `INSERT OVERWRITE DIRECTORY`, storage `LOCATION`s, data source `OPTIONS`, credentials and queries of files by their path (`` delta.`/Volumes/…` ``): they move data between the warehouse and storage outside the catalog;
- `CREATE`, `ALTER` and `DROP` of catalogs, shares, recipients, providers, connections, credentials, external locations, foreign catalogs, clean rooms, functions and procedures, and `CALL`: they reach other workspaces, accounts, storage or databases, or run code;
- functions that reach outside the warehouse's tables: `read_files`, `cloud_files`, `read_kafka`, `read_kinesis`, `read_pubsub` and their kin read files and streams; `http_request` calls HTTP endpoints; `ai_query` and every `ai_*` function call models and AI services billed apart from the warehouse; `vector_search` and `remote_query` reach serving endpoints and other databases; `secret()` and `list_secrets()` read secret scopes; `java_method` and `reflect` run Java methods on the warehouse and `python_exec` runs Python code; and `IDENTIFIER(…)` names an object only when the statement runs. Neither GateRook's reading of a statement nor Unity Catalog's table grants describe what these do. Functions of your own run with what their definitions allow: grant `EXECUTE` on them deliberately;
- `EXPLAIN` of anything but a query, and `ANALYZE … COMPUTE STATISTICS` as a read: it writes a table's statistics.

`databricks_execute` runs one `INSERT`, `UPDATE`, `DELETE`, `MERGE`, `TRUNCATE`, `CREATE`, `ALTER` or `DROP` of a table, view or schema, `COMMENT`, `OPTIMIZE`, `VACUUM`, `ANALYZE`, `REFRESH`, `RESTORE`, `UNDROP`, `REORG`, `CONVERT TO DELTA` or a repair (`MSCK`, `FSCK`, `REPAIR`). The approval shows the exact statement, its parameters, the connection's default catalog and schema and the target. What runs is the approved statement, once; Databricks' answer reports the rows it affected (`num_affected_rows` and its kin). A change is never retried and never cancelled: an answer lost after the request was sent reports the outcome as unknown, and a change still running at the call's deadline is left running and reported as unknown with its statement id. Delta applies a DML statement whole or not at all; check a table after a failed maintenance statement.

## Verify

The connector's tests run against a fake workspace over HTTPS with a test CA in every build: its token endpoint, the Statement Execution API and Unity Catalog's API. There is no Databricks emulator, so the formats of values, result chunks and errors come from Databricks' documentation. JVM checks do not establish native-image or installer compatibility, nor behaviour against Databricks itself.

Databricks documents the [Statement Execution API](https://docs.databricks.com/api/workspace/statementexecution), [Unity Catalog's tables API](https://docs.databricks.com/api/workspace/tables/list), [OAuth machine-to-machine authentication](https://docs.databricks.com/aws/en/dev-tools/auth/oauth-m2m), [Unity Catalog privileges](https://docs.databricks.com/aws/en/data-governance/unity-catalog/manage-privileges/privileges) and [parameter markers](https://docs.databricks.com/aws/en/sql/language-manual/sql-ref-parameter-marker).
