Code gw-code gw-code-block gw-tok-*

Literal values are shown verbatim in JetBrains Mono with ligatures off: what a human approves or copies is exactly what runs. Use gw-code for one literal inside a sentence, a table cell or a heading (tool names, slugs, hosts, paths, token prefixes). Use gw-code-block for anything multi-line: the exact statement in an approval request, a config snippet, command output. Do not use either for emphasis, for keyboard shortcuts (gw-kbd) or for a value the user edits (gw-textarea--code). Masked values are never real secrets: they render as ‹masked›.

Syntax tokens

Token colours come from --gw-color-code-*, each at least 4.5:1 on the code background in all four modes. Colour is decoration here: the text itself is the content. A block can omit the header.

gw-tok-keyword      SELECT, WHERE, true, null
gw-tok-string       'cancelled', "POST"
gw-tok-number       48213, 1.5
gw-tok-comment      -- comments, # comments
gw-tok-function     now(), count(*)
gw-tok-property     JSON, YAML and TOML keys
gw-tok-punctuation  , ; ( ) = { } [ ]
gw-tok-secret       ‹masked›, ‹masked:pii›, ‹secret:vault://kv/stage/db#password›

Hidden and look-alike characters

Text a human confirms must be visible, not only verbatim. A bidi override, a zero-width character, a tab or a trailing space renders as a boxed escape (gw-tok-invisible); a non-ASCII letter that looks like ASCII is boxed as itself (gw-tok-confusable). Both carry the code point in title, and a warning above the block counts them.
