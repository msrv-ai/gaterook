Secrets

How credentials are stored, encrypted and handed to a connector at call time, and where they come from.

Secrets are used only by the connector that needs them and are never sent to the agent

Nobody can view a stored value, here or through the API. To change one, replace or rotate it.

How it works

The agent never sees a secret value, only the result of the call.

  1. 1Store or reference

    Paste the value once, or point to Vault, GCP Secret Manager or AWS Secrets Manager.

  2. 2Encrypted with the master key

    AES-256-GCM with its own data key, wrapped by the key in ~/.gaterook/master.keyset.

  3. 3Decrypted only inside the connector, at call time

    Decrypted at call time inside the connector and sent only to its own resource. External MCP servers keep theirs in their environment while they run.

  4. 4The agent gets the masked result

    Known secret formats and PII in the output become ‹masked› before the agent sees it.

Keep a current copy away from this computer. Without it, the secrets stored here can't be recovered if this computer is lost.

Copies of ~/.gaterook/ include the key next to the database. Exclude master.keyset from Time Machine and other folder backups, so a copy of the database never travels with its key.

Protects against other users and copied files, not against programs you run, including AI agents with a terminal.

Permissions are 0644: other users on this computer can read the key

Something changed them after the gateway set 0400. Fix them, then rotate the key if you don't trust the other accounts.

OS protection unavailable

No keyring answered (Linux without a Secret Service, for example), so the key file is protected by its permissions only. Install or unlock a keyring, then restart the core.

The key is in a synced folder

The data folder is inside iCloud Drive, so every device on that account gets a copy of the key and the database. Quit the app, move the folder out of iCloud Drive, then start it again.

Back up master key

Without a copy, the 8 secrets stored here can't be recovered if this computer is lost.

Primary key ID

File name

Without one, the copy is the plain key: whoever has it and a copy of the database can read every secret. You need the passphrase to restore.

A save dialog asks where the copy goes. Pick a place off this computer, such as your password manager or an encrypted drive, never next to database backups. macOS asks for your password before the copy is written.

Rotate master key

No downtime: calls keep working while the gateway switches keys.

  1. 1 Add a new key Generated on this computer and made primary in the keyset.
  2. 2 Re-wrap 8 data keys Each secret's data key is wrapped again with the new key. Secret values are never written out.
  3. 3 Disable the old key Only after every data key is re-wrapped, so a call in flight never loses its key.
  4. 4 Back up the new key Copies made before rotation can't open the re-wrapped data keys.

Disconnect HashiCorp Vault?

stage-db, prod-replica, dev-vm and prod-vm fail on their next call: their reference and short-lived credentials come from Vault.
