Policies

Guardrails for every connection, per environment: what agents may read, how much and how fast, and who approves changes. Stage inherits each value it doesn't set from dev; prod has its own, stricter defaults.

View denied calls in Activity

Mutations need approval by default

Database writes, restarts, runbooks that change state and HTTP requests other than GET wait for a person by default. Set a tool to Bypass on its endpoint to run it without approval. Policy denials and limits still apply in every mode.

Users and roles, server mode preview

Allow any shell command on prod-vm?

Agents could ask to run anything on prod-vm, not only its two runbooks. Commands need your approval unless ssh_exec uses Bypass. Policy denials and limits still apply.

Reset the dev policy to its defaults?

The 4 values set on dev go back to dev defaults: table allowlist to none, namespaces to none, personal data masking to none, masked fields to none. Stage follows wherever it sets nothing itself.

Reset the stage policy to dev?

The 6 values set on stage go back to dev: row limit 500 to 1,000 rows, max response 256 to 512 KB, allowed services to none, regions to none, resource patterns to none, allowed base URLs to none.

Reset the prod policy to its defaults?

The 2 values set on prod go back to prod defaults: table allowlist to none, masked fields to none. Your unsaved approval timeout is discarded.
