Welcome to GateRook

Give your AI agents one MCP URL to your databases, servers, logs and clusters, without handing them a single password.

Skip setup

  • Your agent never sees secrets

    Passwords and keys stay encrypted on this computer. The gateway adds them to each call and masks them in results.

  • You approve every change

    Writes, restarts, deploys and SSH commands wait for you, shown exactly as they will run. No answer means no.

  • Every call is logged

    Who called which tool, with which arguments, what was decided and how long it took. The log is append-only.

Protect your master key

It encrypts every secret you store here.

GateRook created this key when it first started. Each secret gets its own data key, sealed with this one, and the file lives apart from the database and its backups: a copied database alone reveals nothing. It protects against other users and copied files, not against programs you run, including AI agents with a terminal.

Key file

~/.gaterook/master.keyset
Permissions
0400 · only your user can read it
Format
Google Tink keyset, sealed with a key from the macOS Keychain

Without one, the copy is the plain key: whoever has it and a copy of the database can read every secret. You need the passphrase to restore.

A save dialog asks where the copy goes. Pick a place off this computer, such as your password manager or an encrypted drive. Together with the database the copy unlocks your secrets, so guard it like a password.

Not backed up yet

Without a copy, a lost or wiped disk takes every stored secret with it: they can't be decrypted, only entered again. You can back up later from Secrets.

Waiting for the save dialog: pick where the copy of master.keyset goes.

Add a connection

Something your agent may use: a database, server, log store, cluster, cloud account or HTTP API.

PostgreSQL, MySQL, MongoDB, Redis, SSH, logs, Kubernetes, GCP, AWS or any HTTP API. You test it before it is saved, and its password or key is encrypted here and never sent to the agent.

Create an endpoint

One MCP URL, such as http://127.0.0.1:7465/mcp/dev.

Pick the connections and set each tool to Off, Read only or Approval. Tools that change data run only after you approve them, on every environment.

Connect your AI app

Claude Desktop, Codex and Cursor are installed on this computer.

Before anything is written, you see the exact change to the AI app's config and where the backup goes. Claude Desktop and Codex get a short-lived token on the fly, so no token sits in their config. Cursor keeps a token in plain text in ~/.cursor/mcp.json, or signs in through the browser or goes through the bridge instead.

Where this leads

What you are setting up, in the order of the steps. Each step fills in one part of it.

Set it up top to bottom: step 1 protects secrets and resources, step 2 adds a connection that uses them, policies already have safe defaults, step 3 publishes tools on an endpoint and step 4 connects an AI app to it. An agent's call travels the other way: AI app, endpoint (with a token or OAuth), policy (mode, limits, approval), connection, where the secret is injected. The agent never receives the secret.
