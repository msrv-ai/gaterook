  • Overview

    What waits for your approval, your connections and AI apps; a step-by-step guide on first run.

  • Approvals

    Queue of pending mutations with the exact action, countdown and your decision; history of what you decided.

  • Onboarding

    First run: protect the master key, add a connection, create an endpoint, connect an AI app.

Resources · what you connect

  • Connections

    Databases, SSH, logs, Kubernetes, clouds and HTTP APIs with health and environment.

  • Add connection

    Wizard: pick a type, fill the schema form, test, add to an endpoint.

  • Connectors

    Built-in types, no-code templates, signed plugins and external MCP servers.

  • Secrets

    Master key, write-only secrets, external stores and short-lived credentials.

Access · who gets what

  • Endpoints

    One MCP URL per purpose, with its connections, tools, tokens and risk.

  • Endpoint dev

    Wiring, tool modes, tokens, AI apps and settings of one endpoint.

  • AI apps

    One-click connect for Claude Desktop, Codex, Cursor, Antigravity; claude.ai via tunnel.

  • Policies

    Guardrails per environment: SQL, SSH, Kubernetes, HTTP egress, limits, approvals.

  • Playground

    Call a tool by hand and see exactly what the agent receives.

Observe · what agents did

  • Activity

    Every call: query, facets, histogram, events, traces and the event drawer; links in with ?q= and #event-. Plus the log of setup changes.

  • Insights

    Volumes, decisions, approvals, latency, errors and unusual activity.

App

  • Settings

    Authorization, notifications, tunnel, local API, audit retention, backup, appearance.

  • Core starting

    The screen that replaces the app while the local core starts or fails.

Elements

Reusable compositions of components, each with a demo of its states.

  • setup-map

    Light visualisation of what to configure and how it connects, in setup order: secrets and resources, connections, policies, endpoints, AI apps. An agent's call travels the other way.

  • how-it-works

    Compact, collapsible strip of 3–4 numbered steps that explains a mechanism before the user configures it: what happens to a secret, how an AI app is authorized, what one-click Connect writes, three ways to extend connectors.

  • getting-started

    First-run checklist card with a progress summary ('5 of 6 done' + gw-progress) and six ordered steps: Protect your master key, Add a connection, Create an endpoint, Connect your AI app, Try a tool in Playground, Set up approval notifications.

  • approval-request

    The decision UI for one mutation an agent asked for: the exact action, then Deny or Approve and run. A comment is required to approve on prod.

  • approval-notification

    Previews of how the same approval request appears outside the window.

  • tool-policy-list

    What agents may call on one endpoint and how.

  • risk-callout

    Warns about the dangerous combination inside one endpoint: private data + untrusted content + external channel.

  • token-issue

    Access tokens of one endpoint.

  • client-card

    One MCP client (Claude Desktop, Codex, Cursor, Antigravity, claude.ai): whether it is installed and connected, which endpoint it uses, how it connects (bridge extension, config file, public URL via tunnel), how it authenticates, and the next step.

  • connection-form

    The schema-driven Configure step of Add connection (PostgreSQL demo).

  • connector-card

    One connector type in the catalog.

  • event-detail

    Everything about one logged call, in the order a developer asks about it.

  • log-explorer

    The query and filter zone above the Activity events table, reused as the Insights filter bar.

  • settings-layout

    Grouped settings.

  • status-screen

    Stands in for the whole window while the gateway core is unavailable: fixed, z status-screen, on the window canvas, no gw-shell.

  • command-palette

    ⌘K / Ctrl+K entry point to the whole app.

  • status-tile

    Compact card per connection or AI app: name, state in words, at most one action.
