Tool policy list

What agents may call on one endpoint, and how: every tool grouped by its connection, with its MCP annotations, the mode picker Off · Read only · Approval · Bypass and per-tool limits over the environment policy. Bypass runs calls without approval while preserving policy limits. Used on endpoint detail (Tools & policies), Policies and Playground.

Theme

Endpoint dev: all tools

Default state: the 14 tools of five of the eight dev connections (orders-mongo, cache-redis and aws-stage are collapsed out of the demo), grouped by the connection they run on. Destructive tools offer Off, Approval or Bypass, and the reason sits under the picker. The limits of sql_query are open: the row limit overrides the dev policy, the other two are inherited. http_request has one override while closed. “Set all to…” changes a whole connection.

Tools of an external MCP server or plugin

The 26 tools of github-mcp just added to endpoint dev (4 shown, under the names agents see). Annotations of an external tool come from the server, not from the gateway, so each row says “Declared by github-mcp, not verified”. github-mcp declares none, so no tool is declared read only: all 26 start in Approval and stay approval, bypass or off, and Read only is unavailable with its reason (native disabled: the option would remove the approval). A tool that a server or plugin does declare read only, and not destructive, can go to Read only, but only after you confirm it for that one tool: the option is unavailable with its reason and a Confirm button beside it. The plugin Jira Service Desk below shows it, as if added to dev.
