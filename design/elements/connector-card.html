Kind and trust

The same words, tones and icons on every card. Built-in connectors carry one badge: kind and trust are the same fact.

Built-in
Ships with the core and updates with it. No separate trust badge.
Template
Declarative tools (SQL or a command with typed parameters). No code runs.
Plugin
A Java plugin, run by the gateway in its own process. Runs code: check the signature.
MCP server
An external MCP server behind the gateway: its tools get modes, approvals and audit.
Signed
The catalog key verified the package. Install without extra steps.
Unsigned
No valid signature. Install asks in a danger confirmation that names the risk and needs an explicit acknowledgement. Tools of plugins and MCP servers say “Declared by <server>, not verified” next to their annotations.

Picker: Add connection, step 1

Radio cards grouped by category, as in step 1 of Add connection. One radio group across all categories, so arrow keys move through every type. Built-in types say so with their tool count (the Logs back ends Loki, GCP Cloud Logging, AWS CloudWatch and OpenSearch are built in, not plugins); installed plugins and templates carry their kind and trust badges. A catalog plugin that is not installed yet (ClickHouse) stays visible and focusable but unavailable: aria-disabled, its reason in the description.
