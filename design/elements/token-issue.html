Token issue

Access tokens of one endpoint: issue a token, show it once, then list it only by its prefix with its lifetime, last use and a revoke that names it. Used on endpoint detail (Tokens) and Settings › Authorization.

Tokens table

Only the prefix is listed, never the token. Claude Desktop (the .mcpb bridge) and Codex (the gw-bridge headers helper) never hold a stored token: they get a short-lived one on the fly, so their rows show how, not a prefix, and Revoke ends the AI app's grant. An expiry under 7 days gets a warning badge, “Last used” opens Activity filtered by the token, and Revoke asks for confirmation that names it. Expired and revoked tokens stay listed for the audit trail.

Issue token dialog

For apps that need a pasted bearer token (MCP Inspector, Cursor and Antigravity through their config file, scripts); Claude Desktop and Codex never need one, and Cursor and Antigravity can go through the bridge instead. Connect never writes a token into a client's file for a prod endpoint. Name, lifetime (6 months / 184 days by default) and the fixed endpoint, then the result step with the only copy of the token; its initial focus is Copy. Desktop tokens have no IP allowlist (server mode only: see the preview below). In the app one dialog swaps its body (data-step goes from form to result); here two dialogs are chained. The result step has no close button: Done needs “I've stored this token”. Use the buttons to open each state.
